# roguelike-hackslash（仮題「冥府の迷宮」）

Top-down 2D **manual-action** co-op roguelite (up to 3 players online), dark-fantasy mood in the style of Death Must Die.
Unity 6000.6.2f1 (URP 2D), C#, Netcode for GameObjects 2.13.3. PC first, mobile later.
Design docs: `Docs/01_GameDesign.md` (concept, classes, perks, meta), `Docs/02_TechnicalDesign.md` (architecture, sync, art pipeline).
Communicate with the user in Japanese. The user directs from their phone; do implementation and verification end-to-end
without asking them to work in the Unity Editor. **Graphics/feel are the user's top priority** — check screenshots after visual changes.

## Architecture in one paragraph
All game logic runs on the host in `Game.Core.RunSimulation` (pure C#, partial: core/rooms, `.Combat` abilities & synergies,
`.Enemies` telegraphed AI). `Game.Gameplay.RunDirector` (scene NetworkObject) ticks it at 30 Hz, mirrors state into
NetworkVariables, sends `SimEvent`s (reliable named messages, `EventCodec`) and enemy snapshots (unreliable, `SnapshotCodec`).
Every peer, host included, presents events via `RunDirector.EventReceived`. Player movement is owner-authoritative
(`NetworkTransform` Owner + `PlayerMover`, which also performs dodge/dash-slash travel); inputs go up via
`NetPlayer.SendInputRpc` (press counters). Class/mastery/trinkets travel as a `Loadout` JSON in the connection payload;
each device keeps its own `ProfileData` (`ProfileStore`). Random-affix gear (`Core/Items`) is on hold and unused.

## Pixel art
All art is generated by code in `Assets/_Project/Scripts/Editor/Art/` (`ArtGenerator`): humanoids are ASCII parts posed
per frame by `HumanoidRig` and rasterized by `PixelRenderer` (auto shading, outlines, weapon smears); effects/tiles by
`ProceduralArt`. Output sheets + `Resources/Sheets/*.asset` (`SpriteSheet`) played at runtime by `PixelAnimator`.
Enlarged previews land in `Logs/art/` — look at them after changing art.

## Commands (batch mode — fail if the project is open in the Unity Editor)
```
powershell -File Tools/VerifyAll.ps1            # builder + EditMode + PlayMode + Windows build + 3-player net test
powershell -File Tools/RunMethod.ps1 -Method Game.EditorTools.PrototypeBuilder.Build   # art + prefabs + scenes
powershell -File Tools/RunTests.ps1 -Platform EditMode
powershell -File Tools/RunMethod.ps1 -Method Game.EditorTools.PlayerBuild.BuildWindows
powershell -File Tools/NetTest.ps1              # host(warrior)+2 clients(mage, ranger), bots, Logs/net/
powershell -File Tools/Screenshots.ps1 -Class mage -Times "10,22,34"   # Logs/shots/
```
Player flags: `-autosolo`, `-autohost <n>`, `-autojoin <ip>`, `-botmove`, `-class warrior|mage|ranger`, `-autoquit <s>`,
`-screenshot <path> -screenshotat <s1,s2,..>`, `-profile <name>`, `-localonly`.

## Gotchas
- MonoBehaviours must live in a file named after the class (Unity can't attach them otherwise).
- `UnityEngine.UI.SafeArea` exists in ugui 2.6 — don't create a same-named class.
- Engine modules aren't listed by default in this template; add `com.unity.modules.*` when an API is missing.
- NetworkObject ids (`GlobalObjectIdHash`) are only computed in `OnValidate`; the builder forces it via reflection.
- Netcode registers message types after the first scene's Awake — never start a session from Awake (LobbyView waits a frame).
- The builder reloads assets by path before using them; NGO's prefab processing can invalidate earlier references.
- Named messages over ~1.2 KB need chunking (Unreliable/ReliableSequenced are not fragmented).
