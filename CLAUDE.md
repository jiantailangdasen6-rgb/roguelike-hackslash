# roguelike-hackslash — Labyrinth Survivor（ラビリンス・サバイバー）

Top-down 2D **manual-action** co-op roguelite (up to 3 players online), dark-fantasy mood in the style of Death Must Die.
Unity 6000.6.2f1 (URP 2D), C#, Netcode for GameObjects 2.13.3. PC first, mobile later.
Source: **public** repo `jiantailangdasen6-rgb/roguelike-hackslash` (remote `origin`, push `main` after committing).
Anything committed is visible to everyone: never commit secrets, keys or personal data.
**Start here when resuming: `Docs/DevLog.md`** (history, decisions, current status, known issues, next steps).
Design docs: `Docs/01_GameDesign.md` (concept, classes, perks, meta), `Docs/02_TechnicalDesign.md` (architecture, sync, art pipeline), `Docs/03_Dungeon.md` (the area maps: rooms joined by doors, explored apart).
**Every line the user sees must be Japanese** — including one-line progress notes between tool calls, replies right
after background-task notifications (they arrive in English; don't drift), and end-of-turn summaries. The user has had
to point out English replies several times. The user directs from their phone; do implementation and verification end-to-end
without asking them to work in the Unity Editor. **Graphics/feel are the user's top priority** — check screenshots after visual changes.
**Always publish finished changes to the browser version** (BuildWeb → DeployWeb → CrossTest; no need to ask). Keep every
automated run **silent** (-autoquit/-botmove/-mute mute the game; Edge gets --mute-audio) and default volumes low.

## Architecture in one paragraph
All game logic runs on the host in `Game.Core.RunSimulation` (pure C#, partial: core/spawning, `.Dungeon` the area map (`Core/Sim/Dungeon.cs`: rooms placed apart in the world, several fought at once, pedestals, boss door, way down), `.Bosses` boss trials, `.Combat` abilities & synergies,
`.Enemies` telegraphed AI). `Game.Gameplay.RunDirector` (scene NetworkObject) ticks it at 30 Hz, mirrors state into
NetworkVariables, sends `SimEvent`s (reliable named messages, `EventCodec`) and enemy snapshots (unreliable, `SnapshotCodec`).
Every peer, host included, presents events via `RunDirector.EventReceived`. Player movement is owner-authoritative
(`NetworkTransform` Owner + `PlayerMover`, which also performs dodge/dash-slash travel); inputs go up via
`NetPlayer.SendInputRpc` (press counters). Class/mastery/trinkets/gear travel as a `Loadout` JSON in the connection payload
(and again via `CampDirector.UpdateLoadoutRpc` when changed in the camp); each device keeps its own `ProfileData`
(`ProfileStore`). Gear (`Core/Items`, `BagView`, `VaultView`) is kept between runs. Sessions start in the walkable camp
(`Camp` scene: `CampDirector` spawns avatars and departs when everyone stands in the gate, `CampView`/`CampPanels`;
data in `Core/Run/Camp.cs`); after a run the host brings the party back (`GameSession.ReturnToCamp`). Requests:
`Core/Run/Quests.cs` + `QuestTracker` (counted from events on every device).

## Pixel art
All art is generated by code in `Assets/_Project/Scripts/Editor/Art/` (`ArtGenerator`): humanoids are ASCII parts posed
per frame by `HumanoidRig` and rasterized by `PixelRenderer` (auto shading, outlines, weapon smears); effects/tiles by
`ProceduralArt`. Output sheets + `Resources/Sheets/*.asset` (`SpriteSheet`) played at runtime by `PixelAnimator`.
Also `PropArt` (props, traps, area tiles), `IconArt` (perk/trinket icons), `SkinArt` (class colour skins).
Enlarged previews land in `Logs/art/` (props.png = contact sheet) — look at them after changing art.

## Rooms, gimmicks, audio
Room layouts/obstacles/traps: `Core/Sim/Arena.cs` + `RunSimulation.Arena.cs`, drawn by `ArenaView` (one look per area).
Audio is rendered offline by `Editor/Audio` into `Resources/Audio/*.wav` (gitignored; the builder renders it when missing):
`powershell -File Tools/RunMethod.ps1 -Method Game.EditorTools.Audio.AudioGenerator.Generate -Tag '\[AudioGenerator\]'`.

## Commands (batch mode — fail if the project is open in the Unity Editor)
```
powershell -File Tools/VerifyAll.ps1            # builder + EditMode + PlayMode + Windows build + 3-player net test
powershell -File Tools/RunMethod.ps1 -Method Game.EditorTools.PrototypeBuilder.Build   # art + prefabs + scenes
powershell -File Tools/RunTests.ps1 -Platform EditMode
powershell -File Tools/RunMethod.ps1 -Method Game.EditorTools.PlayerBuild.BuildWindows
powershell -File Tools/NetTest.ps1              # host(warrior)+2 clients(mage, ranger), bots, Logs/net/
powershell -File Tools/CampTest.ps1             # 3 players: depart, wipe, back to camp together, depart again
powershell -File Tools/Screenshots.ps1 -Class mage -Times "10,22,34"   # Logs/shots/
```
Browser version (GitHub Pages, public repo `jiantailangdasen6-rgb/roguelike-web`, branch `gh-pages`, build output only):
```
powershell -File Tools/BuildWeb.ps1             # fonts subset + builder + tests + WebGL build (Builds/WebGL)
powershell -File Tools/ServeWeb.ps1             # local test at http://localhost:8099/
powershell -File Tools/DeployWeb.ps1            # publish to https://jiantailangdasen6-rgb.github.io/roguelike-web/
powershell -File Tools/OnlineTest.ps1           # Relay: Windows host + 2 Windows clients join by room code (Logs/online/)
powershell -File Tools/CrossTest.ps1            # Relay: Windows host + headless Edge on the published page (?onlinejoin=CODE&botmove)
powershell -File Tools/ResumeTest.ps1           # Relay: host connection breaks, "continue" room, clients rejoin with their characters
```
Online co-op uses Unity Relay over secure WebSockets (room codes; browsers can't host LAN). The Unity Cloud project
(id f2ea130d-3bfa-4974-8a26-2babfbec2d80, Relay enabled) is set as `cloudProjectId` in `ProjectSettings/ProjectSettings.asset`;
without it the online buttons explain it's unavailable. Verified desktop<->desktop and desktop host <-> browser client.
Solo uses NGO's `SinglePlayerTransport` (no sockets, works in browsers).

Player flags: `-startroom <n>`, `-difficulty easy|normal|hard|nightmare`, `-downat <s>` (host knocks a teammate down), `-autosolo`, `-onlinehost <n> -codefile <path>`, `-onlinejoinfile <path>`, `-autohost <n>`, `-autojoin <ip>`, `-botmove`, `-class warrior|mage|ranger`, `-autoquit <s>`,
`-screenshot <path> -screenshotat <s1,s2,..>`, `-profile <name>`, `-localonly`, `-doorwait <s>` (bots linger by the open doors for screenshots),
`-freezeat <s> -freezefor <s>` (stall the main thread once: transport robustness), `-pingat <s1,..>` / `-pingroomat <s1,..>` (co-op pings, seconds after the run scene loads).
`-failat <s>` (host acts as if its connection broke; the run is kept) + `-autoresume` (reopen a room straight into it): `Tools/ResumeTest.ps1`.
Online co-op over Relay: always re-check with `OnlineTest.ps1 -HostExtra "-freezeat 50 -freezefor 4"` after network changes (LAN NetTest never shows queue overflows).

## Gotchas
- **Japanese text uses bundled subset fonts** (`Resources/Fonts/Body.ttf`, `Title.ttf`, from `Tools/SubsetFonts.ps1`, full fonts
  in `Tools/FontSubset/cache/`, not in git). Browsers have no OS fonts: after adding new Japanese text, re-run the subset or
  the new characters won't render. Credits in `Docs/credits.md`.
- Tools/*.ps1 run under Windows PowerShell 5.1, which reads BOM-less UTF-8 as the ANSI code page: keep scripts ASCII-only.
- WebGL: Gzip + decompression fallback (Brotli failed on Pages for the card game), Medium stripping with `Assets/link.xml`;
  profiles are saved in PlayerPrefs there (no file system).
- MonoBehaviours must live in a file named after the class (Unity can't attach them otherwise).
- `UnityEngine.UI.SafeArea` exists in ugui 2.6 — don't create a same-named class.
- Engine modules aren't listed by default in this template; add `com.unity.modules.*` when an API is missing.
- NetworkObject ids (`GlobalObjectIdHash`) are only computed in `OnValidate`; the builder forces it via reflection.
  Every builder run gives the scene-placed RunDirector a **new** id, written to `Resources/BuildStamp.txt`; hosts refuse
  joiners with another stamp. So a Windows build used with the web build (CrossTest) must come from the same builder run:
  BuildWeb -> BuildWindows (no builder in between) -> DeployWeb -> CrossTest. `-stamp <s>` fakes a mismatch.
- The web page is our own template `Assets/WebGLTemplates/Labyrinth` (fills the window); UI canvases use Expand scaling.
- Netcode registers message types after the first scene's Awake — never start a session from Awake (LobbyView waits a frame).
- The builder reloads assets by path before using them; NGO's prefab processing can invalidate earlier references.
- Named messages over ~1.2 KB need chunking (Unreliable/ReliableSequenced are not fragmented).
- GitHub Pages takes up to a minute to serve a new deploy: run CrossTest only once the published `Build/*` sizes match
  `Builds/WebGL/Build` (an older page has another build stamp and is refused: "browser never joined").
- From the Bash tool, run scripts as `powershell -ExecutionPolicy Bypass -File Tools/xxx.ps1` (the default policy blocks them).
